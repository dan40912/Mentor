# 實驗台：零人工介入的案例與量測

這個資料夾有三個「交給 Mentor 一路做到完」的範例任務，以及量測它們的方法。目的有兩個：

1. 示範怎麼寫一份 AI 從頭做到尾、中間不用問人的需求。
2. 量出 Mentor 在哪裡還會停下來等人，作為改善工具的依據。

## 怎麼跑

```sh
node scripts/lab.mjs                                   # 平行跑這裡全部案例
node scripts/lab.mjs examples/lab/01-mini-game.md      # 只跑一個
```

- 會用你已登入的 CLI 與「角色與設定」的預設指派，真的消耗額度。
- 資料放在 `.lab-home/`（已加入 `.gitignore`），報告在 `.lab-home/runs/<時間>/`。
- 腳本扮演「人」：Mentor 每次停下來等人，腳本照固定規則代答，並記成一次人工介入。代答規則寫在 `scripts/lab.mjs` 的 `POLICY`。
- 同一個卡點連續 3 次就判定為迴圈並停止，避免空燒額度。Ctrl+C 會先停掉 AI 再寫報告。

## 結果（2026-10-09，Codex gpt-6-sol medium）

| 版本 | 完成 | 人工介入 | AI 提問 | 每案時間 |
|---|---|---|---|---|
| v1 prompt（標準流程，3 個工作項目） | 0／3，全部卡在 W1 骨架 | 小遊戲 4 次後仍卡；簡報 1 次後卡；網站修 2 輪後停 | 0 | 7～11 分鐘後放棄 |
| v2 prompt（快速流程，1 個工作項目） | 3／3 | 每案 1 次，只有最後確認成果 | 0 | 4.3～5.7 分鐘 |
| v1 prompt，Mentor 修正第 1～5 點後 | 3／3 | 每案 3 次，全是確認成果（每個工作項目一次） | 0 | 7.4～10.3 分鐘 |

最後一列表示：同一份寫得不夠好的 prompt，工具修好後也能跑完。剩下的停頓都來自下面「需要你決定」的第 6 點。

v2 的三份成果我另外親手確認過：`node check.mjs` 都是 `ALL PASS`。在瀏覽器實際打開，遊戲可以開始、移動、掉落；網站在 375px 寬沒有水平捲動；簡報 `#4` 會直接跳到流程圖頁。

## 寫 prompt 的規則（v1 → v2 學到的）

1. **把 Grill 會問的題目先答完。** 讀者、看完要做的決定、篇幅、素材、視覺都寫清楚，再加一句「不要提問，直接判定資訊足夠」。v1、v2 都是 0 提問。
2. **驗收標準只寫 AI 能用檔案或指令驗證的條件。** 「用瀏覽器打開可以玩」AI 做不到，它會誠實回報 BLOCKED，整條鏈就停了。人要看的部分明寫「最後由我確認，不屬於 AI 的驗收範圍」。
3. **不要把流程寫成驗收標準。** 「執行後貼出輸出」會被大綱轉成驗收條件，但驗收階段看不到執行者的回報，所以永遠 NOT_RUN。
4. **給一支可執行的 `check.mjs` 當驗收主體**，並要求驗收者讀 `check.mjs` 確認每項真的有斷言。這樣可以擋掉「沒有數字所以數字檢查通過」這種空洞的 PASS。
5. **指定工作項目的數量。** 小任務只拆 1 項。拆越多項，完全自動模式要人確認的次數越多（原因見下面第 4 點）。
6. **不要用沒有依據的形容詞。** v1 寫「挑 3 個最常見的痛點」，素材沒有排名，AI 只好自己解讀。
7. **要求 AI 交一份 `RETRO.md`。** 五個固定小標，其中「指示不清楚的地方」和「要做到零人工介入還缺什麼」是改下一版 prompt 最直接的來源。

## Mentor 可以改善的地方

依造成的人工成本排序。每一條都有實驗證據。

### 已修正（2026-10-09）

第 1～5 點已修正，另外修了重跑時發現的第 10、11 點。修正後用 v1 prompt 重跑，三案都完成，結果見上表。

1. **驗收階段看不到執行者的回報。** `prompts.E`（`src/coach.js:151`）只給檔案，不給 `item.log`。流程型條件因此永遠 NOT_RUN，而 NOT_RUN 會被當成 FAIL（`src/coach.js:790`）。v1 網站為此修了 2 輪，約 5 分鐘白跑。
   已修正：C 的 prompt 禁止流程型與要人用眼睛確認的驗收條件；E 會收到執行者最後一次回報，標明「自述，不算證據」。
2. **「需要你補資訊」說錯原因。** 執行者回報 BLOCKED 是因為沒有瀏覽器，首頁卻顯示「需要你補資訊」（`src/coach.js:332`）。人要打開工作項目的 log 才知道真正原因。
   已修正：停下的說明直接帶出 AI 回報的「未完成」那一段，分成「需要你補資訊」與「做不下去」，同一原因連續停下會標「第 N 次」。
3. **人下指令觸發的修正不計入修正上限。** 自動修正有 2 輪上限（`src/coach.js:324`），但經由 `instruct` 的修正沒有，v1 小遊戲因此重複 4 次同一個 BLOCKED。
   已修正一半：同一原因連續停下會在說明標出次數，讓人一眼看出代答沒用。人下的指令仍然不設上限，因為那是人的決定。
4. **驗收用整份任務的標準審骨架。** v1 簡報的 W1 骨架被要求「完成 W2 內容與 W3 的 RETRO.md」，F 就在 W1 把全部做完。骨架閘門失去作用，W2、W3 變成重工。
   已修正：E 只核對這一項的驗收條件，骨架版會註明「內容不完整是預期的」；D 也被要求只做這一項。
5. **服務結束時不會收掉 CLI 子程序。** 停掉 Mentor 後，`codex exec` 和它的 sandbox 程序仍在背景跑。
   已修正：服務收到 SIGINT／SIGTERM 時先停掉執行中的 CLI。用會卡住的假 CLI 驗證過，停服務後子程序從 1 個變 0 個。
10. **回報的檔名格式太嚴格。** 模型把 FILES 寫成 `` `deck.html` `` 或 `[deck.html](/絕對路徑:12)`，Mentor 認不得，判成「回報完成但沒有產出檔案」。
   已修正：解析時去掉反引號、引號、Markdown 連結與行號。
11. **素材沒有基準 hash。** v1 簡報的 W3 要證明沒改過素材，一直停下來向人要「任務開始前的 SHA-256」。
   已修正：建立任務時記下產出資料夾既有檔案的 SHA-256，放進每個階段的 prompt。

### 需要你決定

6. **完全自動模式中，每一段依賴都要人確認一次。** `ready()`（`src/tasks.js:130`）要求前置項目是 DONE，而 AI 驗收通過只到 REVIEWED。標準流程「骨架 → 完整版 → 回顧」至少要停 2 次。
   這和 CONTRIBUTING 的原則「AI 不能替人驗收」有關，所以要你決定：完全自動模式下，是否讓 REVIEWED 先解鎖後續項目，最後再一次由人確認全部成果。
7. **Grill 沒有回合上限。** 用假 CLI 測試時，AI 每次都問同一題，自動模式會一直停下等人回答。完全自動模式可以考慮在第 2 輪後改成「用預設值並標成假設」。

### 之後

8. **沒有瀏覽器驗證能力。** 三個案例的 RETRO.md 都寫到：要零人工介入，缺的是能用指定寬度打開頁面、截圖、檢查水平捲動的方法。目前只能用 `check.mjs` 做靜態與 `node:vm` 模擬。這也代表 AI 會針對可檢查的條件最佳化，不會針對畫面好不好看。
9. **感測器「大綱每段都有出現」誤報。** 它用段落標題字面比對 HTML（`src/sensors.js:39`），大綱標題寫成「1. 頁首導覽 nav」就判 FAIL，網站與遊戲兩案都因此出現假警報。

## 回饋表單

確認成果、自動停下、任務完成這三個時刻，Mentor 會在任務詳情問一題 1–5 分，附可複選的標籤和一句選填補充。一次只問一題，可以按「這次不評」略過，略過後不會再問同一題。

- **給 AI 的方向。** 負面標籤會對應到具體做法，例如「做太多」對應「只做這一項要求的範圍」。這些做法和低分的原話會一起放進下一個任務的 prompt。同專案有 3 筆以上回饋時只用同專案的，不夠時用全部任務。
- **給你看的趨勢。** 首頁「你的回饋」顯示三個時刻的平均分數、AI 學到的方向，以及你最近的原話。
- **實驗台不評分。** 腳本代答不代表真人觀感，所以 `scripts/lab.mjs` 不會送出評分，以免汙染方向。

## 代答規則的限制

實驗裡「確認成果」由腳本代按，沒有真的看。所以「1 次人工介入」量的是流程上的最少停頓，不代表成果品質已被人確認。品質要另外看 `check.mjs` 的輸出與實際打開成果。
