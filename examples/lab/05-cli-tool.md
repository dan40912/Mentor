# 任務：做一個 Node.js CLI，把一場會議時間換算成多個時區

## 交付
產出資料夾內要有這四個檔案：
1. `tz.mjs`：CLI 本體，只用 Node.js 20 內建功能（`Intl`、`node:util` 的 `parseArgs` 等），不安裝套件。
2. `tz.test.mjs`：用 `node:test` 寫的測試。
3. `README.md`：給同事看的使用說明，台灣繁體中文。
4. `RETRO.md`：這次任務的回顧，格式在最後一節。

## 讀者與情境
跨國團隊的 PM，在終端機快速查「台北下午 3 點開會，其他人是幾點」。不懂時區縮寫也要能用。

## 已經決定的事（不要再問）
- 用法：`node tz.mjs "2026-11-03 15:00" --from Asia/Taipei --to America/New_York,Europe/London,Asia/Tokyo`
- `--from` 預設 `Asia/Taipei`。`--to` 必填，逗號分隔，只接受 IANA 時區名稱。
- 輸出一個對齊的表格，每列一個時區：時區名稱、當地日期（`YYYY-MM-DD`）、當地時間（24 小時制 `HH:mm`）、星期幾（中文，例如「週二」）、與來源時區的時差（例如 `-13h`、`+1h`）。如果當地日期和來源不同天，在日期後加 `（前一天）` 或 `（隔天）`。
- 加 `--json` 時改輸出 JSON 陣列，欄位：`zone, date, time, weekday, offsetHours, dayShift`（`dayShift` 是 -1、0、1）。
- 錯誤處理：時間格式錯、時區名稱不存在、沒給 `--to`，都要印出一行台灣繁體中文的錯誤說明到 stderr，並以結束碼 2 結束。`--help` 印出用法並以 0 結束。
- 必須正確處理夏令時間：紐約 2026-11-01 結束夏令時間。

## 驗收標準（只寫 AI 自己能用檔案或指令驗證的條件）
1. 驗收者自己執行 `node --test tz.test.mjs`，全部通過、結束碼 0。
2. `tz.test.mjs` 至少涵蓋這 8 項，驗收者要讀測試檔確認每項真的有斷言：
   台北 15:00 換算紐約、倫敦、東京的結果；跨日標示（台北 08:00 → 紐約前一天）；夏令時間切換前後（紐約 2026-10-31 與 2026-11-02 的時差不同）；`--json` 輸出欄位與型別；時間格式錯時結束碼 2；時區不存在時結束碼 2；沒給 `--to` 時結束碼 2；`--help` 結束碼 0。
   測試要用 `node:child_process` 實際執行 `tz.mjs`，不能只測內部函式。
3. 驗收者自己執行 `node tz.mjs "2026-11-03 15:00" --to America/New_York,Europe/London`，輸出有兩列，紐約為 `2026-11-03`、`02:00`、`-13h`。
4. `README.md` 有安裝需求、三個用法範例（含 `--json`）、錯誤碼說明；`RETRO.md` 五個小標都有內容。

## RETRO.md 格式
用這五個小標，每項 1～5 條，具體到檔名或步驟：
1. 我自己決定的事：決定了什麼、為什麼。
2. 指示不清楚的地方：哪一句讓你猶豫，你怎麼解讀。
3. 工具或權限造成的限制：例如不能開瀏覽器、不能執行某指令。
4. 最浪費時間的一步：發生什麼事、下次怎麼避免。
5. 要做到零人工介入還缺什麼：需要的資訊、權限或驗證方法。
