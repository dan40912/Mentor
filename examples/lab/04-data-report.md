# 任務：把 Q3 門市銷售 CSV 做成一頁 HTML 報表

## 交付
產出資料夾內要有這四個檔案：
1. `report.html`：一頁報表，單一檔案。CSS 與 JS 全部內嵌，不載入任何外部檔案、字型或 CDN。圖表一律用內嵌 SVG 手寫，不用圖表函式庫。
2. `build.mjs`：只用 Node.js 20 內建模組。讀 `sales-2026q3.csv`，算出所有數字，產生 `report.html`。報表裡的數字一律由它算出來，不手寫。
3. `check.mjs`：只用 Node.js 20 內建模組的自我檢查。`node check.mjs` 全部通過時印出 `ALL PASS` 並以 0 結束；任何一項失敗就印出原因並以 1 結束。
4. `RETRO.md`：這次任務的回顧，格式在最後一節。

## 素材（已放在產出資料夾，是唯一的資料來源）
- `sales-2026q3.csv`：欄位 `date,store,item,unit_price,qty`，2026 年 7～9 月三間門市的銷售。營收 = `unit_price × qty`。
不修改這份檔案。

## 讀者與情境
虛構公司「山嵐烘焙所」的老闆，用筆電看 2 分鐘。看完要決定：Q4 要不要把行銷預算集中到表現最好的門市。

## 已經決定的事（不要再問）
- 報表區塊，順序固定：
  1. 標題與一句結論：哪間門市 Q3 營收最高，比第二名多幾 %。
  2. 三個數字卡：Q3 總營收、總杯數（qty 加總）、平均單價（總營收 ÷ 總 qty，四捨五入到整數）。
  3. 長條圖：三間門市的 Q3 營收。
  4. 折線圖：三間門市各月營收（7、8、9 月），三條線。
  5. 表格：四個品項各自的 Q3 營收與占比，依營收由高到低排序。
  6. 資料說明：資料期間、筆數、計算方式。
- 金額格式：`NT$` 加千分位，例如 `NT$1,234,560`。百分比到小數點後一位。
- 色彩：白底、深灰字，三間門市各一個顏色，在長條圖、折線圖、圖例一致。色盲友善：不能只靠紅綠區分。
- 每張 SVG 要有 `<title>` 與 `<desc>`，`<desc>` 用一句話寫出圖表重點。
- 用語：台灣繁體中文。

## 驗收標準（只寫 AI 自己能用檔案或指令驗證的條件）
1. 驗收者自己依序執行 `node build.mjs` 與 `node check.mjs`，後者印出 `ALL PASS`、結束碼 0。
2. `check.mjs` 自己重新讀 CSV 獨立計算一次，不能 import `build.mjs` 的函式；至少比對這 6 項：總營收、總 qty、平均單價、三間門市 Q3 營收、各月各門市營收、四個品項營收與占比。比對的對象是 `report.html` 裡實際出現的文字。
3. `check.mjs` 也要檢查：6 個區塊依序存在；兩張 SVG 都有 `<title>` 與 `<desc>`；結論句裡的門市名稱與百分比和計算一致；沒有 `src="http`、`href="http`、`@import`。驗收者要讀 `check.mjs` 確認每項真的有斷言。
4. `RETRO.md` 五個小標都有內容。

瀏覽器實際觀看由我在最後確認成果時自己做，不屬於 AI 的驗收範圍。執行與驗收都不要因為沒有瀏覽器而回報 BLOCKED 或 NOT_RUN。

## 限制
- 只能在產出資料夾內建立或修改檔案。不安裝套件，不使用網路。

## 遇到未知時的授權
上面沒寫到的細節，AI 直接選合理預設值，不要停下來問我。每個自己決定的預設值寫進 `RETRO.md` 的「我自己決定的事」。

## 給各階段的指示
- 任務制定與 Grill：讀者、成功標準、篇幅、素材與視覺都已在上面回答。不要提問，直接判定資訊足夠可以擬定大綱。
- 擬定大綱：只拆 **1 個工作項目 W1「完成報表、build.mjs、check.mjs 與 RETRO.md」**，owner 是 ai，acceptance 直接用上面 4 條驗收標準的原文。不要另外拆骨架或其他項目，不要建立需要人做的項目。
- 執行：做完後依序執行 `node build.mjs` 與 `node check.mjs`，失敗就修到通過。回報時貼上最後一次的完整輸出。
- 驗收：只採信你這次自己執行的輸出與你讀到的原始碼，不採信執行者的回報。每條都要寫出檔名與行號。

## RETRO.md 格式
用這五個小標，每項 1～5 條，具體到檔名或步驟：
1. 我自己決定的事：決定了什麼、為什麼。
2. 指示不清楚的地方：哪一句讓你猶豫，你怎麼解讀。
3. 工具或權限造成的限制：例如不能開瀏覽器、不能執行某指令。
4. 最浪費時間的一步：發生什麼事、下次怎麼避免。
5. 要做到零人工介入還缺什麼：需要的資訊、權限或驗證方法。
