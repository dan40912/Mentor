# 階段 5：專案學習筆記 MD

## 共同規則（每階段相同）

- Repo：[dan40912/Mentor](https://github.com/dan40912/Mentor)。先 `git fetch origin`，以 `main` 為基底；若前一階段 PR 尚未合併，改以前一階段分支為基底，並在 PR 說明註明。
- 完整產品規格：`prompts/mentor-chat-harness-prompt.md`。若 `main` 沒有這個檔案，執行 `git fetch origin claude/zen-feynman-l7nkx5 && git show origin/claude/zen-feynman-l7nkx5:prompts/mentor-chat-harness-prompt.md` 取得。先讀完再動工。
- 限制：零 runtime 依賴、Node 20+、原生 JS、無 build 步驟；測試用 `node:test` 與 `tests/fixtures/fake-cli.mjs`，不得呼叫真實 AI；保留 127.0.0.1、Host／Origin、session、CSRF、Idempotency-Key 與預覽路徑檢查；不得提交 `vault/`、`outputs/`、設定或真實執行紀錄。
- **只做本階段範圍。** 發現範圍外的問題，寫進回報的「建議後續」，不要順手改。
- 不得以跳過、刪除、放寬斷言或改測試期望來讓測試通過，除非能證明原測試期望本身錯誤，並在回報中逐條說明。
- 完成後：推送分支，向 `main` 開 **Draft PR**，不要 merge。最後輸出下方「交付回報」，使用者會把它交給驗收者（Claude）檢查。驗收者會自己抓分支、跑測試、讀 diff，回報內容必須與實際一致。

## 背景

任務檔 `vault/TASK-<id>.md` 是給系統用的正本，含 `awc:begin`／`awc:end` 之間的 JSON 狀態區塊，不適合閱讀。使用者的願景是：專案做完後，整個專案變成一份**讀得懂、學得會**的 Markdown 筆記，清楚看到狀態、進度、決策與結論，內化成自己的知識。

本階段新增「專案學習筆記」，與系統狀態檔分開。

## 任務

### 1. 產生與更新

- 位置：`MENTOR_HOME/vault/notes/<專案標題>.md`（處理 Windows 保留檔名、非法字元、同名衝突；任務 ID 寫在 Properties 中作為穩定識別）。
- 任務狀態改變時（建立、計畫核准、run 開始或結束、使用者決策、驗收、學習保存）重新產生筆記中的系統區塊。
- 使用者在系統區塊以外手寫的內容必須保留。系統區塊以明確標記包住（例如 `<!-- mentor:begin -->`／`<!-- mentor:end -->`）。使用者若修改了系統區塊內的內容，下次產生前要偵測到並保留使用者版本（例如另存衝突段落並提示），不得默默覆蓋。
- 產生過程不呼叫 AI；只從任務紀錄、runs、決策、成果、檢查結果、學習紀錄組合。需要 AI 的部分（「我學到的」候選、「回顧問題」）在任務完成時由使用者觸發一次，產出後須使用者確認才寫入。

### 2. 筆記結構

```markdown
---
title: <專案標題>
type: 專案筆記
mentor_task: <任務 ID>
status: 製作中 | 待驗收 | 已完成
updated: <日期>
tags: [<類型>, <專案>]
---

# <專案標題>

> 一句話結論（完成後填；未完成寫「尚未完成」）

## 目標
給誰看、看完要做什麼決定、成果形式。

## 進度
| 部分 | 負責 AI | 狀態 | 成果 |

## 我們怎麼做
拆解方式與理由；為什麼選這些 AI。

## 關鍵決策
| 決策 | 選擇 | 理由 | 誰決定 | 日期 |

## 結論與成果
成果連結（相對路徑）、主要結論、關鍵數字與來源。

## 驗收狀態
已由你確認 / 自動檢查通過 / 尚未驗證，分開列出。

## 我學到的
可重用的做法與原則（使用者確認後才出現）。

## 回顧問題
3 個幫助記憶的問題（使用者確認後才出現）。

## 過程紀錄
按時間的重要事件摘要；完整紀錄連回任務檔。
```

- 狀態用白話（沿用階段 1 的術語對照）。未驗證的事明確寫未驗證；不得編造未發生的過程。
- 「我學到的」中使用者勾選「以後都要這樣做」的短規則，走既有的 Memory／學習流程；其餘只留在筆記。

### 3. 介面與 Obsidian

- 任務詳情與「工作中」面板提供「開啟專案筆記」；對話中問「這個專案目前怎樣？」時可引用筆記內容並附連結。
- 「存到 Obsidian」：若已配對 Obsidian 插件，寫入使用者選定的 Vault 資料夾（沿用既有橋接的權限與版本檢查）；未配對則提供下載 `.md`。
- 筆記在 Obsidian 關閉 Mentor 插件與主題時仍可正常閱讀。

## 驗收清單（驗收者會逐條檢查）

- [ ] `npm test` 全部通過，測試數不少於基線。
- [ ] 建立任務、核准計畫、run 完成、決策、驗收後，筆記對應段落更新（各有測試）。
- [ ] 系統區塊外的手寫內容保留；系統區塊內被使用者修改時不被默默覆蓋。
- [ ] 檔名處理：非法字元、Windows 保留名、同名不同任務的測試。
- [ ] 未驗證項目不會被寫成已驗證；決策、理由、日期與紀錄一致。
- [ ] 「我學到的」與「回顧問題」在使用者確認前不出現在筆記中；勾選的規則進入既有學習流程。
- [ ] 產生筆記不呼叫 AI（以測試證明）。
- [ ] 存到 Obsidian 走既有橋接權限；未配對時可下載。
- [ ] 回報附一份以虛構任務產生的完整筆記範例。
