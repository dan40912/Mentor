# 階段 6：成果預覽、出處與判斷決策卡

## 共同規則（每階段相同）

- Repo：[dan40912/Mentor](https://github.com/dan40912/Mentor)。先 `git fetch origin`，以 `main` 為基底；若前一階段 PR 尚未合併，改以前一階段分支為基底，並在 PR 說明註明。
- 完整產品規格：`prompts/mentor-chat-harness-prompt.md`。若 `main` 沒有這個檔案，執行 `git fetch origin claude/zen-feynman-l7nkx5 && git show origin/claude/zen-feynman-l7nkx5:prompts/mentor-chat-harness-prompt.md` 取得。先讀完再動工。
- 限制：零 runtime 依賴、Node 20+、原生 JS、無 build 步驟；測試用 `node:test` 與 `tests/fixtures/fake-cli.mjs`，不得呼叫真實 AI；保留 127.0.0.1、Host／Origin、session、CSRF、Idempotency-Key 與預覽路徑檢查；不得提交 `vault/`、`outputs/`、設定或真實執行紀錄。
- **只做本階段範圍。** 發現範圍外的問題，寫進回報的「建議後續」，不要順手改。
- 不得以跳過、刪除、放寬斷言或改測試期望來讓測試通過，除非能證明原測試期望本身錯誤，並在回報中逐條說明。
- 完成後：推送分支，向 `main` 開 **Draft PR**，不要 merge。最後輸出下方「交付回報」，使用者會把它交給驗收者（Claude）檢查。驗收者會自己抓分支、跑測試、讀 diff，回報內容必須與實際一致。

## 背景

使用者的日常任務是做簡報、整理資訊、做判斷。現在成果多為 HTML 或 Markdown，需要另開預覽。本階段讓成果**直接在 Mentor 裡看、指著改、下載成熟悉的格式**，並為判斷類任務提供決策卡。

既有的預覽機制（每個任務登記成果、路徑與 symlink 檢查、大小與類型白名單）必須沿用，不得放寬。

## 任務

### 1. 簡報逐頁預覽與指著改

- 簡報成果（既有 HTML 簡報格式，參考 `examples/lab/02-mini-deck.md`）在右側面板以逐頁縮圖 + 放大檢視呈現；鍵盤左右鍵可翻頁。
- 使用者可選取一頁（或一頁中的文字），輸入修改意見，例如「這頁太多字，改成三點」。意見附上頁碼與選取文字，送到對話成為 `instruct`，確認後交給負責的代理走既有修改流程。
- 預覽在沙箱化的 iframe 中顯示（不得執行能存取 Mentor 頁面或 API 的腳本；沿用或強化既有 CSP 與 sandbox 屬性）。

### 2. 資訊整理的出處

- 整理類成果中的每條重點若附來源標記，點擊可看原文片段（來自使用者提供的素材）。
- 自動檢查：成果中的關鍵數字必須能在素材中找到（參考 `examples/lab/` 中的做法），找不到的標示「無來源」，並列入檢查結果。檢查只是建議，不代表人工驗收。

### 3. 判斷決策卡

- 判斷類任務（提案卡的成果形式為「決策建議」）的成果包含結構化 JSON（或 Markdown 中可解析的區塊）：選項、各選項的好處、代價、依據（附來源）、還不知道的事、AI 的建議與理由。
- 介面以決策卡並列呈現選項。使用者按下自己的選擇並可補一句理由；選擇與理由寫入任務紀錄並出現在專案學習筆記的「關鍵決策」。
- AI 的建議只標示為建議；只有使用者按下的選擇才算決定。

### 4. 下載

- 至少提供：Markdown、可列印的 HTML（瀏覽器列印成 PDF，簡報需每頁一張）。
- `.pptx`／`.docx`：只有在能以零依賴、可測試的方式產生時才提供；否則介面誠實標示「尚未支援」並說明替代方式。不得引入 runtime 依賴。

## 驗收清單（驗收者會逐條檢查）

- [ ] `npm test` 全部通過，測試數不少於基線。
- [ ] 簡報預覽：逐頁縮圖、放大、鍵盤翻頁；選頁送出修改意見會帶頁碼與選取文字，且需確認才執行（有測試）。
- [ ] 預覽 iframe 無法存取父頁面或 Mentor API（有測試或明確的 sandbox／CSP 證據）；既有路徑與 symlink 檢查未放寬。
- [ ] 數字來源檢查：素材中找不到的數字被標示「無來源」（有測試）。
- [ ] 決策卡：AI 建議與使用者選擇分開記錄；使用者選擇寫入任務與學習筆記（有測試）。
- [ ] 下載 Markdown 與可列印 HTML 可用；`.pptx`／`.docx` 若未支援，介面如實標示。
- [ ] 沒有新增 runtime 依賴；介面文字通過禁用術語掃描。
- [ ] 320／390／1360 px 檢查通過，回報附截圖說明（虛構資料）。
