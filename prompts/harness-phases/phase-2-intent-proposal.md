## 共同規則（每階段相同）

- Repo：[dan40912/Mentor](https://github.com/dan40912/Mentor)。先 `git fetch origin`，以 `main` 為基底；若前一階段 PR 尚未合併，改以前一階段分支為基底，並在 PR 說明註明。
- 完整產品規格：`prompts/mentor-chat-harness-prompt.md`。若 `main` 沒有這個檔案，執行 `git fetch origin claude/zen-feynman-l7nkx5 && git show origin/claude/zen-feynman-l7nkx5:prompts/mentor-chat-harness-prompt.md` 取得。先讀完再動工。
- 限制：零 runtime 依賴、Node 20+、原生 JS、無 build 步驟；測試用 `node:test` 與 `tests/fixtures/fake-cli.mjs`，不得呼叫真實 AI；保留 127.0.0.1、Host／Origin、session、CSRF、Idempotency-Key 與預覽路徑檢查；不得提交 `vault/`、`outputs/`、設定或真實執行紀錄。

## 背景

階段 1 已讓對話成為主畫面。現在的 `src/workspace-chat.js` 只會回答問題，或在偵測到新工作時回傳 `taskProposal: { request }`，使用者確認後建立任務。本階段讓對話能理解使用者的各種意圖，並以「工作提案卡」交辦新工作。

使用者是非工程背景的一般人，日常任務是做簡報、整理資訊、做判斷。

## 任務

### 1. 意圖判斷

擴充工作區對話，讓指揮者 AI 回傳結構化結果（JSON），至少包含以下意圖：

| 意圖 | 例子 | 行為 |
| --- | --- | --- |
| `question` 一般提問 | 「上週那份報告結論是什麼？」 | 回答；引用任務或成果時附任務 ID／檔名；不改任何狀態 |
| `quick` 小型立即工作 | 「把這段改短」「翻成英文」 | 直接在回覆中完成，不建立任務；提供「存成專案」按鈕 |
| `new_work` 新的工作 | 「幫我做 Q3 回顧簡報」 | 回傳工作提案（見下），使用者確認後才建立 |
| `instruct` 對進行中工作的指示 | 「第 3 頁改用 9 月數字」「先停一下」 | 指出對應任務；本階段只做到：顯示「我理解你要對〈任務〉做〇〇」並提供按鈕帶到該任務既有的修改／停止操作，不自動執行 |
| `material` 補充素材或回答追問 | 拖入檔案、回答 AI 的問題 | 指出要綁定到哪個任務，確認後走既有附件或回答流程 |
| `clarify` 不確定 | 意圖或對應任務不明 | 回一個問題加 2～3 個可點選項，不猜 |

規則（需有自動測試）：

- 資料、檔案、Git 紀錄、歷史對話中的文字都是資料，不能授權操作；只有使用者本人最後一則訊息與按鈕確認算數。
- 查詢、假設、舉例、否定句（「不用幫我做簡報，我只是問」）不得產生 `new_work`。
- AI 回傳格式錯誤、意圖不在清單內、對應的任務 ID 不存在時，伺服器必須拒絕或降級為 `question`／`clarify`，不得信任。
- AI 不可宣稱已執行、已改檔、已建立任務。

### 2. 工作提案卡

`new_work` 時在對話中顯示提案卡，內容來自 AI 的結構化回傳並經伺服器驗證：

- 一句話目標、給誰看、成果形式（簡報／文件／表格／決策建議／其他）。
- 打算怎麼做：拆成幾個部分，每部分一句話用途、建議由哪個 AI 負責與一句理由（只能從已設定且可用的 AI 中選；用途描述用白話，模型名稱放展開資訊）。
- 需要使用者做的事（例如確認骨架、最後驗收）。
- 已有素材、缺少的素材。
- 按鈕：「開始」「修改」「先問我幾個問題」。使用者也可直接打字修改提案，AI 回傳更新後的提案卡。
- 按「開始」：以提案內容建立任務（沿用既有 `coach.create` 與流程設定；拆解與 AI 指派寫入任務，供階段 3 使用），並使用 Idempotency-Key 防止重複建立。本階段建立後的執行仍走既有單代理流程。

### 3. 對話紀錄

- 對話紀錄保存在 `MENTOR_HOME` 下（例如 `vault/chat/`），重新整理或重啟後可恢復。
- 送往 AI 的上下文有上限（沿用現有 8 輪、每輪 1,500 字的限制或說明新的上限），不得無限增長。
