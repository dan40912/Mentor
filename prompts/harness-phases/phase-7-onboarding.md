# 階段 7：首次上手引導、白話錯誤與真實冒煙測試

## 共同規則（每階段相同）

- Repo：[dan40912/Mentor](https://github.com/dan40912/Mentor)。先 `git fetch origin`，以 `main` 為基底；若前一階段 PR 尚未合併，改以前一階段分支為基底，並在 PR 說明註明。
- 完整產品規格：`prompts/mentor-chat-harness-prompt.md`。若 `main` 沒有這個檔案，執行 `git fetch origin claude/zen-feynman-l7nkx5 && git show origin/claude/zen-feynman-l7nkx5:prompts/mentor-chat-harness-prompt.md` 取得。先讀完再動工。
- 限制：零 runtime 依賴、Node 20+、原生 JS、無 build 步驟；測試用 `node:test` 與 `tests/fixtures/fake-cli.mjs`，不得呼叫真實 AI；保留 127.0.0.1、Host／Origin、session、CSRF、Idempotency-Key 與預覽路徑檢查；不得提交 `vault/`、`outputs/`、設定或真實執行紀錄。
- **只做本階段範圍。** 發現範圍外的問題，寫進回報的「建議後續」，不要順手改。
- 不得以跳過、刪除、放寬斷言或改測試期望來讓測試通過，除非能證明原測試期望本身錯誤，並在回報中逐條說明。
- 完成後：推送分支，向 `main` 開 **Draft PR**，不要 merge。最後輸出下方「交付回報」，使用者會把它交給驗收者（Claude）檢查。驗收者會自己抓分支、跑測試、讀 diff，回報內容必須與實際一致。

## 背景

目標使用者不是工程師。目前使用 Mentor 需要自行安裝 Node、在終端機啟動、自行安裝並登入 AI CLI；錯誤訊息（額度、登入、逾時）偏技術。本階段降低上手門檻，讓錯誤都有白話說明與下一步，並以真實 AI 跑一次完整流程作為收尾證據。

## 任務

### 1. 首次上手引導

- 第一次開啟（或沒有任何可用 AI 時）顯示引導頁：
  - 自動偵測 Codex、Claude Code、GitHub Copilot CLI 是否已安裝、是否已登入（沿用 `agents.js` 的 `diagnose`）。
  - 每個 AI 用白話說明狀態與下一步（例如「已安裝，尚未登入：在終端機輸入 `claude` 並依指示登入，完成後按『重新檢查』」），附各家官方說明連結。
  - 「用示範資料試玩」：使用獨立的示範資料目錄，並清楚標示 AI 回覆為模擬（沿用或擴充 fake CLI 機制），絕不在示範模式中呼叫真實 AI 或寫入使用者真實資料。
  - 「之後再說」可略過；隨時可從設定重新開啟。
- 引導完成後進入對話畫面，第一則訊息提供三個範例：「幫我做一份簡報」「幫我整理這幾篇文章」「幫我比較兩個選項」。

### 2. 白話錯誤

- 盤點使用者可能看到的錯誤（額度用完、登入過期、逾時、AI 回傳格式錯誤、檔案太大、網路或連線中斷、版本衝突 409、session 過期）。
- 每個錯誤顯示：發生了什麼、已完成的工作是否保留、建議的下一步按鈕（換一個 AI 接手、稍後重試、重新整理、重新登入說明）。原始錯誤放在「詳細紀錄」。
- 用量以白話呈現（例如「這個專案用了 Claude 4 次」）；費用只能標示為「估算」，不推論帳單。

### 3. 啟動便利性

- 提供 Windows（`.cmd`）與 macOS／Linux（`.command`／`.sh`）的雙擊啟動腳本：檢查 Node 版本、啟動服務、自動開啟瀏覽器；Node 不存在時顯示白話說明與下載連結。
- README（中、英）新增「給非工程使用者的上手方式」，內容與實際行為一致。

### 4. 真實冒煙測試

- 以虛構的簡報任務，在一台已登入真實 AI CLI 的機器上跑完整流程：對話交辦 → 提案卡 → 多代理執行 → 預覽 → 修改一頁 → 驗收 → 專案學習筆記。
- 記錄於 `docs/verification/`：使用的 AI、日期、每一步結果、失敗與處理。若無法執行真實測試，明確寫「未執行」與原因，**不得以 fake CLI 結果代替**。

## 驗收清單（驗收者會逐條檢查）

- [ ] `npm test` 全部通過，測試數不少於基線。
- [ ] 引導頁：已安裝已登入、已安裝未登入、未安裝三種狀態皆有 fake CLI 測試；「重新檢查」更新狀態。
- [ ] 示範模式不呼叫真實 AI、不寫入真實資料目錄（有測試），介面標示為模擬。
- [ ] 錯誤盤點清單附在回報中；每種錯誤都有白話訊息與下一步，且有測試覆蓋主要幾種（額度、登入、409、session 過期）。
- [ ] 啟動腳本在 Node 缺少或版本過低時給出白話說明；README 中英文同步。
- [ ] 真實冒煙測試紀錄存在，或明確標示未執行與原因。
- [ ] 介面文字通過禁用術語掃描；沒有新增 runtime 依賴。
