# 階段 1：對話成為主畫面與介面白話化

## 共同規則（每階段相同）

- Repo：[dan40912/Mentor](https://github.com/dan40912/Mentor)。先 `git fetch origin`，以 `main` 為基底；若前一階段 PR 尚未合併，改以前一階段分支為基底，並在 PR 說明註明。
- 完整產品規格：`prompts/mentor-chat-harness-prompt.md`。若 `main` 沒有這個檔案，執行 `git fetch origin claude/zen-feynman-l7nkx5 && git show origin/claude/zen-feynman-l7nkx5:prompts/mentor-chat-harness-prompt.md` 取得。先讀完再動工。
- 限制：零 runtime 依賴、Node 20+、原生 JS、無 build 步驟；測試用 `node:test` 與 `tests/fixtures/fake-cli.mjs`，不得呼叫真實 AI；保留 127.0.0.1、Host／Origin、session、CSRF、Idempotency-Key 與預覽路徑檢查；不得提交 `vault/`、`outputs/`、設定或真實執行紀錄。
- **只做本階段範圍。** 發現範圍外的問題，寫進回報的「建議後續」，不要順手改。
- 不得以跳過、刪除、放寬斷言或改測試期望來讓測試通過，除非能證明原測試期望本身錯誤，並在回報中逐條說明。
- 完成後：推送分支，向 `main` 開 **Draft PR**，不要 merge。最後輸出下方「交付回報」，使用者會把它交給驗收者（Claude）檢查。驗收者會自己抓分支、跑測試、讀 diff，回報內容必須與實際一致。

## 背景

Mentor 要從「任務看板 + 表單」轉為「以對話為主的個人工作介面」，使用者是非工程背景的一般人（PM、行銷、行政、研究助理），日常任務是做簡報、整理資訊、做判斷。現在右側聊天（`src/workspace-chat.js` 與 `web/index.html` 中的聊天面板）只是附屬功能，主畫面仍是看板；介面大量露出 A–F、revision、PASS/FAIL、provider、effort 等工程術語。

本階段只處理**版面與文字**，不改意圖判斷邏輯（階段 2）與執行引擎（階段 3）。

## 任務

### 1. 新版面

- 桌面（≥ 1024 px）：左側窄欄為專案清單，分「需要我處理」「進行中」「最近」三組；中間為對話；右側為「工作中」面板（本階段先放現有任務的狀態摘要與成果入口，可收合，階段 4 再做完整代理卡）。
- 手機（390 px、320 px）：對話全螢幕；頂部一條狀態列，例如「2 件進行中・1 件等你」，點開為全頁清單。
- 開啟 Mentor 預設進入對話畫面。既有的「現在／任務／成果與知識／更多工具」、看板、交接中心、回收桶、角色與設定全部保留，移到次要入口（例如左欄底部或選單），功能與網址行為不變。
- 對話中可以點專案名稱開啟既有的任務詳情；關閉後焦點回到原位置。
- 鍵盤操作、焦點管理、`aria` 標示不得退步；尊重 `prefers-reduced-motion` 與深色模式（沿用既有色彩變數）。

### 2. 介面白話化

- 建立術語對照表（例如新增 `web/assets/plain-words.js` 或在既有 `item-names.js` 擴充），至少涵蓋：

| 工程用語 | 介面用語（建議） |
| --- | --- |
| A 任務卡／B 追問／C 計畫／D 執行／E 審閱／F 修改 | 了解需求／確認細節／擬計畫／製作／檢查／修改 |
| revision | 第 N 版 |
| workItem | 工作項目 |
| sensor／自動 check | 自動檢查 |
| PASS／FAIL／NOT_RUN | 通過／未通過／尚未檢查 |
| provider | AI 助手 |
| model | 模型（放在展開資訊） |
| effort | 思考深度 |
| token | 用量 |
| CLI | AI 助手程式 |
| exit code、stdout、stderr | 不在一般介面出現，只放在「詳細紀錄」 |

- 套用到使用者可見的文字：按鈕、標題、狀態標籤、提示、錯誤訊息。原始技術資訊保留在可展開的「詳細紀錄」中。
- 新增自動測試：掃描 `web/index.html` 與 `web/assets/*.js` 中使用者可見的字串，若出現禁用術語（例如獨立的 `revision`、`PASS`、`FAIL`、`provider`、`effort`、`token`、`exit code`、`A–F`、「階段 A」等）且不在「詳細紀錄」或白名單中就失敗。白名單須附理由。
