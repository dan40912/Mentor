# PM 實戰：設計 AI Agent

## 30 秒重點

先定義使用者要完成的任務，再決定哪些步驟交給模型判斷。固定步驟可以用工作流，只有需要依情境選擇下一步時，才增加 Agent 的自主性。

## 退款案例

教學示例：使用者問某筆訂單能退多少。模型理解問題與追問缺漏，後端查訂單歸屬及退款資格並試算。第一版只做查詢及試算，真正退款走既有核准流程。

## 一頁設計表

複製下表，將範例欄換成你的產品。由 PM 主持確認，工程補工具契約，QA 用每一列設計情境。

| 欄位 | 退款案例範例 |
|---|---|
| 讀者與任務 | 已登入的客戶要確認一筆訂單的可退金額。 |
| 完成定義 | 顯示該筆訂單的有效試算金額、幣別與限制。 |
| 模型的決策 | 辨識查詢意圖、追問訂單資訊、解釋後端結果。 |
| 工具契約 | 後端驗證登入身分與訂單歸屬，回傳試算金額、幣別、版本或錯誤類型。 |
| 停止及轉人工 | 無法確定訂單時追問。試算失敗時停止出價，提供重試或轉人工。 |
| 成效指標 | 追蹤合格查詢完成率、轉人工率及權威數值一致率。 |

## 上線前怎麼驗收

- 正常訂單：顯示後端同一版本的金額與幣別。
- 他人訂單：查詢被拒，回覆不揭露訂單資訊。
- 工具逾時：顯示暫時無法確認，提供重試或轉人工。
- 要求執行退款：引導至既有核准流程，查詢工具沒有寫入權限。

設計框架可回看 AI 產品 Spec 與 Scenario Catalog、Agent 代理 與 Guardrails 護欄。
