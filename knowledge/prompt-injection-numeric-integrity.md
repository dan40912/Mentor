# PM 實戰：提示詞注入與數字完整性

## 30 秒重點

模型讀取客服對話與文件時，可能將其中的文字當成指令。PM 可以把資料來源、工具權限和執行核准寫進產品規格。金額等關鍵欄位由權威系統提供，程式負責顯示、核對與執行。

## 退款案例

教學示例：客戶詢問可退多少，退款服務回傳 **TWD 1,250**。直接注入來自對話，間接注入可來自 Agent 讀取的文件。這兩種輸入都可能影響模型行為。即使模型只因理解錯誤而產生 TWD 12,500，顯示層也應以服務欄位為準。

## 照著做：把規則落到系統

1. **產品與資安定邊界。** 外部內容只供參考。查詢、試算、執行使用獨立權限。後端逐次檢查訂單歸屬，執行退款前驗證核准。
2. **工程定義權威欄位。** 用退款服務提供金額、幣別、訂單 ID 和試算版本。頁面用這些欄位渲染。正文若需要金額，也由程式插入同一值。
3. **工程與 QA 定義失敗處理。** 格式檢查只能確認欄位形狀。執行前核對權威資料與核准版本。金額變更、來源衝突或試算過期時停止，重新試算並視情況重新核准。

## 5 分鐘分享與 QA 驗收

前一分鐘講退款案例。接著兩分鐘在白板畫出「外部內容 → 模型 → 後端驗權 → 退款服務」。最後兩分鐘用下表請大家判斷每個情境應在哪一層被攔下。

| 情境 | 預期結果 |
|---|---|
| 文件內容試圖影響查詢範圍 | 只回傳登入身分可讀的資料，未發生未授權操作。 |
| 模型草稿寫 TWD 12,500，服務回傳 TWD 1,250 | 正式金額顯示 TWD 1,250，錯誤草稿在送出前阻擋或修正。 |
| 送出前幣別或試算版本變更 | 停止執行，重新試算並核對核准內容。 |
| 原始帳務欄位收到未授權寫入 | 帳務服務拒絕寫入並記錄結果。 |
