# 初始需求重複傳送檢查

本次只去除同一輪 Prompt 中完全相同的初始需求副本，不摘要或截短使用者要求。A 使用共用背景的原始需求；B／C 只在第一則使用者訊息與原始需求完全相同時，省去那一則重複內容。後續再強調原要求、修正、相似但多了限制的訊息都保留。

隔離虛構壓力範例：初始要求由一句話重複 30 次構成，另有一則後續限制。原始要求本身的 30 次重複仍完整保留，不擅自推測其意義。比較基底與 hash 見同名 JSON。

| 階段 | 減少字元 | 減少 UTF-8 bytes |
| --- | ---: | ---: |
| A | 969 | 1,821 |
| B | 965 | 1,813 |
| C | 965 | 1,813 |

這是傳入 Prompt 文字的確定減量，沒有呼叫真實 AI，不能據此宣稱 Token、費用、延遲或返工率改善。兩項回歸驗證保留後續修正、重申與非完全相同的初始訊息；未取代真實模型品質驗證。既有真實交接 benchmark 中不利結果仍有效，不覆寫它。
