# 交接 Token 比較：2026-10-22

這次實測**沒有證明可重複的 Token 節省**。兩種格式都讓模型正確找回關鍵資訊，但用量結果方向相反；不得只採用第一組作為產品節省宣傳。

## 方法與可重現條件

- macOS、Node v26.7.0、Claude Code 2.1.300。
- requested model：sonnet，effort：low；四次 CLI 回報的模型皆為 claude-sonnet-5-5。
- 同一份固定虛構任務，兩組順序為 full → compact、compact → full；每次新 CLI 工作階段，不使用 resume。
- 完整格式由 buildHandoff 產生；精簡格式由 compactHandoff 產生。歷史包含刻意重複的設計討論，這是壓力範例，不代表一般任務。
- 送出的完整 Prompt：13,723 字元／35,171 bytes；精簡：1,415 字元／2,597 bytes。兩者都含相同檢查指示。
- 每次檢查十個欄位：taskId、revision、goal、next、forbidden、locked、latestCorrection、period、humanAccepted、budget。全部需符合固定真值，禁止把未知預算猜成數字或把 NOT_RUN 誤當通過。
- Claude logical input = input_tokens + cache_read_input_tokens + cache_creation_input_tokens；這個公式限此 provider 的欄位定義。Codex input_tokens 已含快取，不能再次加快取。

## 實測結果

| 組別 | 格式 | CLI logical input | 輸出 Token | 本機時間 ms | 十欄資訊檢查 |
| --- | --- | ---: | ---: | ---: | --- |
| 1 | full | 18,973 | 179 | 9,932 | 全數正確 |
| 1 | compact | 9,033 | 179 | 5,842 | 全數正確 |
| 2 | compact | 44,273 | 179 | 6,646 | 全數正確 |
| 2 | full | 22,508 | 179 | 6,155 | 全數正確 |

第一組精簡輸入少 9,940 Token；第二組精簡輸入反而多 21,765 Token。CLI 背景上下文與快取未被控制，目前無法把差異歸因於交接格式。模型名稱相同也不表示環境上下文相同。

四次回覆都保留必要資訊，只證明這個虛構事實找回測試通過；不證明真正製作的成果品質相等，也不能代替跨 AI 的實際接力、Obsidian 視覺或真人理解驗收。

## 證據與執行方式

[原始報告](handoff-2026-10-22.json) 保留四個樣本、Prompt／fixture SHA-256、模型與用量欄位、檢查結果及 CLI 費用估算；全為虛構任務，沒有帳號或 session metadata。[彙整判定](handoff-2026-10-22-summary.json) 另附原報告 SHA-256，不覆寫原始證據。

這份報告使用初版 schema 1。後續腳本 schema 2 會直接輸出彙整結論與 Node／平台欄位，沒有重跑並改寫上述四個樣本。

```sh
npm run benchmark:handoff
npm run benchmark:handoff -- --run --provider claude --model sonnet --pairs 2
```

第一個指令只列範圍與文字大小，不呼叫 AI。第二個指令呼叫真實帳號共四次，消耗額度，證據保存於隔離 .lab-home；不讀使用者 Vault。一般 npm test 只跑虛構解析與判定測試。

預設兩組，可指定 1～3 組。若品質檢查、模型身分或用量缺失，比例保持未知；Codex 目前沒有可靠的 effective model 回報，因此工具保留它的原始計數，不宣稱可比較的比例。

## 目前能做與不能做的結論

可以確認：精簡格式減少此次送出的文字，且四次資訊找回都沒有遺漏指定條件。

不能確認：穩定節省總 Token、降低帳單或提升真實產出品質。後續須辨識 CLI 自行附加的上下文、重試與快取差異，再擴大任務種類與樣本；不為了做出好看的結果而刪掉不利樣本。
