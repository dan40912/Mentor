# 原生工作回合閱讀 Review

這份紀錄對照「使用者是否能看懂每輪變化」的需求，不是已通過真人或設計驗收的宣告。

1. **UI Structure**：側欄先提供從筆記準備任務；索引、內容草稿、分類及復原集中在「整理筆記與復原」。任務視窗先看目前目標、下一步與最近一輪，先前回合按需展開。
2. **Field Details**：目前目標與下一步來自任務正本；角色以任務整理／需求釐清／計畫草稿／成果製作／AI 審閱／依意見修改表示，機器用的 A–F 保留。結果、AI 自述與檢查分列。舊理解缺失標為未記錄，不用今天的目標補寫。
3. **Redundancy And Clarity Fixes**：避免同時展開全部回合與全部檢查；相同理解不重複顯示。模擬回合另行標示，不冒充真實執行；沒有檢查不代表通過。
4. **Consistency Checks**：Web、原生與普通 Markdown 共用 work-cards 的角色及模擬資料。展開歷史只讀既有紀錄，不呼叫模型、不變更工作。檢查未通過會出現在摘要，不能因收合而藏起目前失敗。
5. **Design Review**：沿用既有 mentor-task／actions 樣式與原生 details／summary 控制，不另造元件系統。間距、窄視窗、鍵盤及實際 Obsidian 渲染仍需桌面實測；Node DOM fixture 不能驗收外觀。
6. **Acceptance Status**：自動回歸核對失敗證據、原理解、缺檢查、模擬標記及只讀歷史；真人六個理解問題、Theme 的閱讀／Live Preview、鍵盤及完整操作尚未驗收。示範庫新增「實機測試：表格與工作回合」，提供不需 AI 帳號的閱讀階段與可選的真實 AI 流程。
7. **One-Sentence Summary**：先看最近變化、保留完整追查，實際可用性仍須由人操作後確認。
