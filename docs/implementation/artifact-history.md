# 每輪成果內容保存（開發中）

D／F 執行前保存任務已登記成果的實際內容；成功解析本輪回報後，僅保存本輪新登記且 SHA-256 相符的成果。工作卡連結保存副本，Web 與 Obsidian 不應在保存副本失效時改讀目前檔案。

舊回合不回填：以前只有檔名與 hash 的紀錄無法重建已覆寫的內容。開工前副本代表當時磁碟內容；若與先前登記 hash 不同，保留 matchesRecorded:false，不冒充先前回合版本。

保存位置為 MENTOR_HOME/vault/artifact-history/<task>/<version>，包含 manifest.json 與編號二進位副本，不位於 agent 的成果工作目錄。每份上限 50 MB、每次 200 份／200 MB；超限或保存失敗不宣稱成功。Manifest 的 digest 登記於任務回合，讀取時比對；內容另核對 SHA-256。這是損壞偵測，無法抵禦能同時修改任務檔與副本的本機使用者。

副本包含完整成果內容，備份及隱私管理應視同原始成果。任務進回收桶時副本一同移動；永久清空會刪除副本，原成果資料夾維持既有行為。此生命週期已以隔離檔案系統整合測試驗證。

此變更不讓 AI 寫入變成原子交易，不提供多程序鎖、不自動還原覆寫檔案，也未涵蓋 C／E 或手動匯入的舊流程。失敗執行仍可能已更動目前成果，開工前副本只提供查閱依據。

已執行測試：tests/artifact-history.test.js（5 項真實檔案測試）及 tests/artifact-history-api.test.js（認證、路由綁定、內容轉義與損壞拒絕）。D／F 執行、失敗寫入後的開工前副本、回收桶還原與永久清空已加入整合測試；Web 的虛構 Markdown 流程及 390px 副本清單已實際操作（見 docs/verification/artifact-history）；原生 Obsidian 實機驗收仍待完成。不能把目前測試視為整體驗收。

接手摘要保留目前成果 hash 及最近三輪副本 manifest 位置／digest／認證 API 索引，不嵌入完整副本內容；更多歷史由工作卡按需取得。外部 AI 需有實際檔案或現有認證才能讀取；索引不是授權或自動驗收。
