## 驗證結果

- 三種尺寸均開啟工作台與聊天，查任務、收合及焦點返回通過。
- 320 px 與 390 px 開啟手機「更多工具」後，導覽保持 168 px。點選角色設定後選單自動收合。
- 三種尺寸實際讀取待核准計畫，預覽視窗沒有水平溢出。320 px 任務視窗的標籤由溢出 70 px 修正為 0 px。
- Obsidian、專案與對話相關 43 項測試通過，涵蓋插件、橋接、索引與分類規劃、草稿、搬移與復原資料、專案及對話。
- 尚需覆蓋有資料的次要狀態、錯誤與復原，以及原生 Obsidian。桌面 Edge 尺寸測試尚未代表真手機或其他瀏覽器。

## 第二輪檢查

- 新任務改用「建立任務並開始釐清」，送出前顯示手動、需核准或自動核准的下一步。Edge 320 px 已點選三種組合並核對提示，沒有送出任務。
- 320 px 手機看板將沒有任務的欄縮為標題與件數。保有任務的欄仍顯示工作卡。
- 回收桶以瀏覽器模擬 API 測有資料時的永久刪除取消、Escape 焦點還原、還原失敗、重試與成功後焦點。沒有永久刪除或修改正式資料。
- 「工作區與 Session」空畫面合併重複說明，加入前往任務對話的入口。
- Windows 的 Obsidian 1.12.7 已實際開啟到儲存庫選擇器。用獨立測試設定直接開啟示範庫時，應用程式顯示 Error，原生工作中心及操作仍待驗證。

## 第三輪檢查

- 交接中心可直接選既有任務，讀取原本的接手摘要並預覽下載。320 px 與 1360 px 實測選擇、失敗重試、真實任務摘要及切回頁面保留選擇。
- 已保存知識可按標題、正文及任務來源搜尋。以模擬筆記檢查多關鍵字、空結果與清除搜尋。
- Obsidian 測試設定的日誌顯示，啟動失敗前剛從內建 1.12.7 切到測試設定下載的 1.15.1 套件。時間順序已核對，錯誤原因尚未證實。

## 原生 Obsidian 與知識來源

- 書庫筆記可從「來源」區塊開啟對應任務。用模擬筆記連至真實任務驗證，關閉任務視窗後焦點會回到來源按鈕。
- 以獨立設定啟動 Windows Obsidian 1.12.7，直接開啟產生的示範庫。確認原生插件載入器無法解析入口內的相對 require；改由插件實際安裝路徑解析，並打包 CommonJS 宣告。
- 原生端已成功配對本機 Mentor，讀取側欄及真實任務，開啟從筆記交辦、索引、分類標籤、AI 草稿送出前預覽、搬移、整理紀錄、任務詳情和接手包。交辦按鈕改為「建立任務並開始釐清」，避免誤以為下一步就會產出方案。
- 在示範庫實際套用索引、查看整理紀錄、預覽並撤回。沒有提交真實 AI 任務、執行正式搬移或寫入正式 Vault。44 項插件及整理相關測試通過。

## 原生整理套用與復原

- Windows Obsidian 1.12.7 的實測索引不把網頁連結計入 Vault 內部連結。搬移原先因此被示範筆記裡的 HTTPS 連結擋下。覆蓋核對現只排除 HTTP(S) 與協定相對網址，內部連結仍要求位置及內容完全相符。
- 示範庫實際選取筆記、預覽並加上標籤，也實際重新命名測試筆記並同步更新另一篇的引用。相關回歸測試 14 項通過。

## 手機聊天與輸入法

- 390 px Edge 觸控模擬中，開啟聊天先聚焦面板的收合按鈕，使用者點輸入框時才喚出鍵盤。收合後焦點回到浮動入口。
- 實測組字事件期間 Enter 不送出、Escape 不收合、Shift+Enter 保留換行、一般 Enter 送出。
- 模擬鍵盤佔去 300 px 的可視區高度，確認聊天面板及輸入框抬升，鍵盤收回後恢復。實體 iOS／Android 鍵盤與瀏覽器行為仍未驗證。

## 原生 AI 草稿結果

- 原本送出後只有短暫通知，使用者要回任務找草稿。現在保留送出結果視窗，標示紀錄位置，提供「查看草稿」及「稍後從任務查看」。尚在預寫時，在同一視窗顯示狀態並可再查。
- Windows Obsidian 實機使用模擬 AI 回應，走完送出、等待、查結果、預覽與套用；在獨立示範庫讀回 Markdown。未呼叫真實 AI。
- 實體 iOS／Android 鍵盤行為仍待設備驗證，已完成 Edge 觸控與可視區模擬。

## 專案說明的鍵盤動線

- 專案說明切換頁籤或上一／下一頁時，重建頁面曾讓焦點落回整頁。現會聚焦選中的頁籤或新頁標題。取消修改回到原按鈕，保存後回到更新的標題；修改歷程項目則回到該筆摘要。
- Edge 320 px 與 1360 px 使用五頁範例驗證切頁、最後一頁、開始編輯、取消、保存及焦點。寫入使用模擬 API。
- 320 px 開啟實際任務的每輪工作卡，三張卡片中的來源路徑曾讓視窗溢出 44 px。長來源與標題會換行，按鈕可在窄版折行，重測視窗無水平溢出。

## 聊天連線失敗與重試

- 查任務失敗時在原訊息下提供「重試查詢」。重試保留原本的查詢與序號參照，只讀取資料。等待時標記忙碌，完成或失敗後清除。
- Edge 模擬第一次讀取斷線，再透過同一則訊息重試，已連到正式本機唯讀 API 並顯示清單。

## 目前優先改善項目

1. 書庫筆記的更新流程。現有合併會另存一篇，使用者需要看得出目前版本及舊版本。更新原筆記應核對版本，外部有改動時保留編輯中的草稿。
2. 聊天自然語句。持續用真實問法檢查查詢、交接與保存，維持明確交辦才建立任務。現在以規則辨識。
3. 實體手機與真實 AI。需確認 iOS／Android 鍵盤、焦點及捲動，以及原生 Obsidian 在 CLI 失敗、等待和回報格式錯誤時的操作。現有證據分別為瀏覽器模擬和原生介面搭配模擬回應。
