# 把每輪工作沉澱成 Mentor 專案知識

## 從 Codex 的 Mentor 專案開始

- **網址**：「收進 Mentor：<網址>。整理成給 PM 的 5 分鐘分享。」
- **本輪成果**：「收進 Mentor。把這輪確定的設計、原因與驗收結果補到原本的筆記。」
- **持續使用**：「這個任務每輪結束都幫我整理新增的專案知識。」
- **取用**：「先從 Mentor 知識庫找我們之前怎麼定義這個問題，再幫我寫規格。」

Codex 依專案根目錄的 `AGENTS.md` 把內容寫進 `knowledge/`。網址策展可沿用本機的 `$kb-curator` 擷取方式；在此專案使用本頁定義的輸出路徑。一般網頁可使用 `defuddle parse <URL> --md`，若命令不可用可透過瀏覽器讀取可存取正文。

2026-11-14 核對 Codex 桌面版聊天「更新 Mentor 到最新版」屬於 Mentor 專案，工作目錄指向本機 Mentor。聊天在首次 `git pull` 請求前已收到根目錄的 `AGENTS.md`，可據此確認桌面版的指引自動載入。同日從 Mentor 專案目錄啟動全新的唯讀 Codex CLI 工作階段，確認 Codex 在讀取檔案前就能區分「這輪可以留什麼」與「收進 Mentor」，並在回答退款試算的驗收條件時讀取知識索引、搜尋及引用兩份教材。

同日以可寫入的隔離副本測試「收進 Mentor」。使用合成的退款金額驗收結果，確認 Codex 將證據補到原教材的 QA 段落、保留合成資料標記並更新日期。比對副本的 `knowledge/` 檔名，確認沒有新增重複篇目。合成紀錄保留在測試副本。

將「收進 Mentor」加到 `kb-curator` 的技能描述後，以新開的唯讀 CLI 工作階段驗收。只使用自然語句交辦，Codex 即選擇並讀取 `kb-curator`，指出正式入庫位置為 `knowledge/`，並說明如何按來源與主題查重及合併原篇。

## AI 如何整併

1. **辨識內容與範圍。** 從使用者提供的網址、文字、已確認的任務成果或決策中擷取有用內容。只收本輪有新資訊且下次用得上的部分。網址附機構、原文與擷取日。任務內容附任務 ID、產出路徑或可查證紀錄。
2. **查重與合併。** 用來源 URL、主題、別名和專案術語搜尋 `knowledge/`。同一來源或相同結論只記一次；有新證據就補到原筆記。主張衝突時保留各自的來源、適用條件與待確認點。若要替換先前決策，留下修改日期、原因和證據。
3. **整理成可讀內容。** 教材先給 30 秒重點，再附案例、照著做、可直接使用的規格／講稿／驗收表及來源。決策筆記記錄選擇、理由、適用條件和如何驗證。保留關鍵數值的單位與來源，標示自擬案例、推論、已驗證與待確認。
4. **存檔與回報。** 用穩定檔名寫入 `knowledge/`，補上主題、關鍵字、來源、更新日期。新增篇目時更新索引，檢查連結與搜尋命中。回報新增或合併的檔案及可供下輪取用的段落。涉及私有客戶資料、未獲授權的附件或憑證時，先提可安全保留的摘要或使用專案的私有資料目錄。

## Mentor Web 裡怎麼做

在同一專案下建立任務，要求 AI 將教材寫成 Markdown 成果，走現有的預覽、執行與確認流程。已確認的短規則可用「成果與知識」裡的學習功能保存，供同專案的下一個任務使用。完整教材目前由 Codex 專案整理入庫，Mentor Web 目前會列出任務成果和學習規則。

若要在 Web 裡完成同一流程，最小可驗收的功能是給「成果與知識」增加「整理成專案知識」：

1. 從目前任務或一個網址產生候選稿，附來源與預計合併的筆記。
2. 讓使用者檢視差異，確認後寫到 `MENTOR_HOME` 下的專案知識目錄。儲存前檢查專案 ID、來源、筆記版本，避免重送產生副本或覆蓋較新的編輯。
3. 專案知識可依標題、別名和段落搜尋。新任務按主題取用相關段落和來源，維持專案隔離，避免把所有文章帶入 prompt。只有明確提升的規則走現有 Memory 注入。
4. 單檔 HTML 可由選定的可分享知識匯出，供手機與離線閱讀。用相同來源重貼、不同專案查找、舊版與新版衝突，以及重啟後仍能讀取做驗收。
