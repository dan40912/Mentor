# Mentor 公開發佈規劃

## 主題：今天交給 AI 的工作，明天變成自己的書庫

**Mentor — Hand off AI work. Keep what you learn.**

給同時用多個 AI 工作的 PM、開發者、研究者與寫作者。每次換 AI 都要重講背景，做完的決策又埋在聊天紀錄裡。Mentor 用一份可編輯的任務紀錄串起交辦、換手與驗收，再把有用的部分存成自己擁有的 Markdown。

GitHub 首頁首屏放一個 45 秒示範：「交給 Codex 擬計畫 → 換 Claude 接手 → 人工驗收 → 存到 Obsidian → 隔天問回同一條決策」。用虛構的產品發佈案例，畫面帶出每次換手保留的目標、限制和證據，以及保存後的真實檔案。首屏提供「免安裝試用」與「在本機啟動」。

## 價值與操作方式

| 我要做的事 | 在哪裡操作 | 目前狀態 |
| --- | --- | --- |
| 把模糊需求交辦清楚 | 任務 → 新任務 → 核對任務卡、回答追問、看計畫 | 既有 |
| 指派哪個 AI 做哪一段 | 更多工具 → 角色與設定，設定 A 任務卡、B 追問、C 計畫、D 執行、E 審閱、F 修改。可在個別任務指定 AI | 既有 |
| 換工具或交給人接手 | 交接中心產生接手 Markdown，附目標、限制、已確認決策、證據和下一步 | 既有 |
| 確認完成並留下一條工作原則 | 任務驗收與「成果與知識」，核對成果後挑選要保留的規則 | 既有 |
| 從 Obsidian 筆記開始 | 在可選的 Obsidian 工作中心配對本機 Mentor，從筆記或選取內容準備任務 | 既有插件 |
| 問筆記、編輯草稿、切換保存位置 | 工作台右上「個人聊天」，選 Mentor 或目前 Vault，編輯 Markdown 後確認目標 | 原型，本機檢索與模板草稿 |
| 用 AI 綜合多份筆記並引用來源 | 右側聊天選範圍、核對來源後送出；在候選稿中比較新增與合併 | 規劃 |

### 第一次使用

1. 不需 AI 帳號，先用虛構案例在公開示範走完「接手、驗收、存一篇筆記」。畫面清楚標明模擬的 AI 回覆。
2. 真實使用時，先在自己的電腦開 Mentor，設定一個已登入的 AI CLI。初次使用可以讓同一個 AI 跑完各階段，下一次再分配不同模型。
3. 建立真實任務。批准計畫、驗收成果，再選擇留下決策、教學或可重用的流程。
4. 選擇 Vault 和資料夾，編輯草稿並確認寫入。下次可以從 Mentor 查相同主題，也可以直接用 Obsidian 開啟、連結與修改。

## 個人書庫

使用者決定筆記進哪個 Vault，例如「個人筆記」「工作知識」「公開教材」。第一次儲存可建立「Mentor/」資料夾，之後沿用上一個位置，確認視窗始終顯示完整目的地。查詢範圍和儲存目的地各自選擇，使用者可以從專案找到內容，再存到自己的閱讀書庫。

每份 Markdown 維持一個清楚的主題，包含重點、做法、案例、來源及驗證結果。以 YAML Properties 記錄標題、類型、專案、標籤和日期。候選稿先用來源與主題查重，命中時顯示差異，使用者選擇合併或另存。外部編輯後版本衝突時保留草稿並重新核對。長期筆記可按資料夾打包匯出，包含附件及相對連結，並測試在新 Vault 還原後可搜尋。

任務紀錄仍用專案任務檔。書庫存使用者確認值得回看的內容。經使用者提升的短規則，才進入 Mentor 的專案學習流程。右側回答附筆記名稱及引用段落，使用者能點回原文。未選用的 Vault 不參與查詢。

## 發佈與部署

| 路徑 | 對象 | 發佈內容與驗收 |
| --- | --- | --- |
| GitHub Pages | 想先試用的人 | 靜態介紹、可操作假資料示範、快速上手與公開書庫範例。Node.js 後端另行部署。[GitHub Pages 文件](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) |
| GitHub 下載或 clone | 要在本機完整使用的人 | 先用 Node.js 20 以上與 npm 啟動；有穩定跨平台驗收後，再做 Releases 預打包與啟動器 |
| 私有雲自架 | 想跨裝置使用的個人 | 規劃 Linux VM 或 Docker Compose、身分驗證、HTTPS、每人獨立資料根目錄、備份與還原。容器資料放持久卷。[Docker 資料卷](https://docs.docker.com/engine/storage/volumes/) |
| 多人託管 | 需要工作區共享的團隊 | 等個人自架實證後評估。須補工作區隔離、權限、密鑰、執行配額與作業隔離 |

現行服務綁在 127.0.0.1 並驗證 Host 與 Origin，這套設計以本機單人使用為前提。私有雲版本要先定義反向代理的信任邊界、可登入的使用者、CLI 工作目錄及憑證隔離，再驗收有權讀寫的範圍。第一版雲端可先支援筆記閱讀、編輯與匯出。需要桌面 Vault 的人可下載 Markdown 或在支援的瀏覽器授權本機資料夾。遠端執行階段只能使用伺服器授權的目錄，有需求再評估安全的本機執行器。

### 跨平台驗收矩陣

| 環境 | 第一版入口 | 必測情境 |
| --- | --- | --- |
| Windows 11 | PowerShell 啟動、Edge 或 Chrome 存 Vault | CLI .cmd 包裝、含空格與中文的資料夾、Windows 保留檔名、無 symlink 權限的測試行為 |
| macOS Apple Silicon | Terminal 啟動、Chrome 或 Edge 寫入 Vault | CLI 路徑、原生檔案選擇與資料夾權限、Unicode 檔名、Obsidian 重開 |
| Linux Ubuntu | Terminal 啟動、Chromium 系瀏覽器寫入 Vault | 大小寫路徑、資料夾擁有者、持久卷、重啟還原 |
| Safari、Firefox 與手機 | 查閱、編輯、下載 Markdown | 資料夾選擇功能以偵測結果呈現；沒有可用能力就提供下載，並測鍵盤、觸控、窄螢幕與減少動態效果。[MDN 目錄選擇器](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker) |

現有從原始碼啟動入口為 npm start，本機預設開在 http://127.0.0.1:4317。npm run demo 使用獨立的示範資料，但後續按下 AI 執行仍可能使用已登入的 CLI。公開靜態 Demo 需要用完全獨立的假資料與假回覆。

## 做出 GitHub 破萬的理由

用一個別人也遇過的問題當品牌入口：「AI 一換人，背景就要重講；專案一結束，做法就找不到。」公開一包可下載的「AI 接手包 + Markdown 書庫」當示範。看完的人即使暫時不部署，也能帶走模板，之後再回來試 Mentor。

- 第一波找同時使用 Codex／Claude 與 Obsidian 的使用者，請他們用自己的小任務，記錄哪一步得靠別人解釋。README 先放英文主敘事，中文版保留完整上手流程。
- GitHub 首發以影片呈現一次真實換手，隨附可重做的示範任務、可下載的書庫、三個 OS 的安裝方式與功能狀態。
- 首月以「三分鐘內完成第一篇保存」及「隔天查得到且能追到來源」作為產品指標。以自願回報或測試場次蒐集，不收集筆記正文。星數是擴散目標，持續觀察真正完成交接、匯出及回查的人數。
- 按次序發佈：① 靜態試用與可攜書庫；② 本機跨平台與真實 CLI 驗收；③ Linux 私有自架、備份還原；④ 有實際團隊需求後再驗收多人版。

## 發佈前驗收

- 新使用者只讀 README 就能開啟示範，在一次操作中看懂交辦、指派、交接與筆記回查。
- 三個 OS 的測試帳號各實跑一輪既有 A–F 工作流，核對 AI 接手時保留的目標、限制和證據。
- 用兩個 Vault 測選擇目標、同名檔、外部改檔衝突、重啟、匯出及還原。使用者可以在 Obsidian 改完再由 Mentor 讀回。
- 本機私有任務、Vault 內容、CLI 憑證和生成檔都在發佈清單外。公開示範只使用虛構資料。
- 私有雲重啟及備份復原後，確認資料、設定與隔離仍正確，才將自架列為正式支援。
