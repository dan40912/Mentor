# 在 Obsidian 使用 Mentor 工作中心

這個分支新增了原生側欄與原創 Theme，直接呼叫同一個本機 Mentor 引擎。沒有把網站嵌進 iframe，也沒有建立第二套任務狀態。尚在開發驗收；下列「已測」與「待驗證」請分開看。

## 安裝到獨立示範庫

需要 Node.js 20 以上與 Obsidian 桌面版。原生插件使用 Obsidian 公開 API、Node crypto，無額外 runtime 套件。

```sh
npm test
npm run package:obsidian
npm start
```

打開終端顯示的本機網址。接著在 Obsidian 開啟 `dist/mentor-obsidian` 作為筆記庫：

1. 外觀設定選擇 Mentor Theme（淺色／深色）。
2. 審閱 `.obsidian/plugins/mentor-work-center/main.js`，再自行啟用 Mentor Work Center。套裝不自動啟用第三方插件。
3. Mentor 網頁按「連接 Obsidian」，讀取權限說明後產生配對碼。
4. Obsidian 命令面板選「Mentor Work Center: 配對本機服務」。貼入配對碼。
5. 若 Mentor 不是預設 4317，輸入實際 `http://127.0.0.1:連接埠`。
6. 打開「00 工作首頁」，從筆記開始。

生成器只寫 repo 的 `dist/mentor-obsidian`，不接受正式 Vault 路徑；不要把自己的筆記放進這個 build 目錄。未提供自動安裝／升級腳本去覆寫現有 Vault。

## 第一個任務

選取相關筆記段落 → 命令「從目前筆記或選取內容準備任務」→ 編輯預填目標 → 閱讀送出的原文 → 確認建立任務。

這一步會把選取內容交給本機服務，再由你已登入的 AI CLI 處理。不是全部只在離線端執行。超過長度限制會停止，不自動截斷來源；請縮小選取範圍。來源在預覽期間被修改時，需重新預覽。

AI 先整理任務與提問。於側欄回答、請 AI 預寫計畫，再確認原始要求、AI 理解、範圍、驗收與具體工作項目。核准綁定你看過的版本及內容識別；過期會拒絕。核准不直接等於開始執行，也不等於驗收通過。

按「交給 AI 執行」後，成果仍需機器檢查與人工確認。每輪卡片分開呈現：當時理解、AI 自述、已登記成果與保存的機器檢查。歷史資料沒有保存理解時，明示未記錄，不拿今天的目標回填。

## 先問問題，不修改成果

Web 任務內展開「有疑問？先問，不改成果」；原生任務視窗選「先問問題，不修改成果」。這會使用 B 階段設定的 AI，以 chat 模式根據任務摘要作答；不附加來源正文，不代表實際讀過成果或整個 Vault。Claude／Copilot 的 chat 工具被停用；Codex 採唯讀 sandbox，仍有讀取能力，因此不能把「未附原文」說成 CLI 無法讀檔。回答仍需以實際證據核對。仍會使用帳號額度。

回答可包含對提問、修改、暫停或不明確意圖的理解。它是待核對的建議：不會自動取消任務、改工作、重新驗收或喚醒自動流程。有修改建議時，按「帶入修正草稿」後仍可編輯，並走既有影響預覽與確認流程。

原始問句、回答與建議保存於任務紀錄。執行 Prompt 排除尚未授權的討論；交接包另標示「問答不是修改或取消授權」。重複請求不重跑模型；重啟後相同識別只回報已保存紀錄。未知或停止的問答不會變成接續原工作。

執行中的工作須先停止並核對；原工作尚在停止復原時不能另啟問答。意圖判讀並不保證正確，明確修正仍可直接走修正入口。

## 工作中補充或修正需求

在任務視窗選「補充或修正這個任務」，填入原文、調整範圍與選填原因，再按「預覽這次修改的影響」。預覽不會呼叫 AI 或啟動自動流程；確認後才會執行並使用帳號額度。來源或任務版本已改變，必須重新預覽。按鍵綁定內容識別與版本，不能拿舊預覽套用另一段文字。

修改已驗收工作時，影響範圍包含所有後續相依項目。舊成果保留，但受影響的驗收不再保持完成：有成果的 AI 項目重新等待檢查，人的工作回到待確認。前置工作未重新確認前，不能先驗收依賴它的成果。重排計畫也會比對工作細節與相依關係；標題相同不代表工作沒變。

問答可提供意圖判讀，但不保證把每個追問、取消及修改都區分正確。請核對回答，並明確選擇要修改的工作或整體計畫。若只是討論，使用問答入口，不確認執行修改。原始要求、這次原文與已確認的讀寫邊界仍保留在任務及交接紀錄。

## 跨 AI 接力

側欄中修改「下一步使用哪個 AI」，只影響後續工作；CLI 需已安裝並登入。執行中的工作先停止並確認結果，不能同時重複寫入。

「準備接手包」從目前任務產生 Markdown 摘要，包含人的補充、邊界、決策、來源索引、任務版本與下一步。可保存為 `Mentor 交接/TASK-id-rN.md`。同版本若已存在，不會覆寫；請閱讀舊快照或明確另存。

接手檔是版本快照，不是新的任務正本。舊版回報仍須由 Mentor 核對。不提供自動額度切換的完成承諾。

## 整理索引：先預覽，再套用

命令「為目前資料夾預寫索引（先預覽）」會讀取目前資料夾的 Markdown，最多 40 篇。根目錄只選直接位於根目錄的筆記；其他資料夾包含其子資料夾。超過上限會停止，請改選較小範圍。

這是以檔名和來源連結產生的確定性索引，不是 AI 讀後摘要，也不會搬移來源。先閱讀來源清單、目標路徑及完整變更；可修改草稿，但修改後必須按「重新預覽修改後草稿」，產生新版本後才能套用。批次方案可排除個別操作。

產出限制在 `Mentor 整理/`；來源或目標已變更會拒絕過期方案。同一方案重複點擊不會重複套用。操作前先保存復原紀錄，部分失敗會逐項顯示，可從「整理與復原紀錄」重試。

復原前先預覽；只有目前內容仍與當時套用結果一致，才會還原舊內容或將新建筆記移到本機回收桶。後來手動修改的內容保留並標示衝突。服務或插件中斷時，必須先確認先前整理已停止，再核對實際檔案；不會自行重跑未知結果。

紀錄位於 `Mentor 整理/復原紀錄/`，包含變更前後內容，會隨 Vault 的同步和備份一起保存，請依筆記的隱私需求管理。此機制不是跨電腦鎖定；外部同步與檔案系統同時修改仍需實機測試。這一版未提供自動分類、搬移或重命名。

## 連線與隱私

- 配對碼 2 分鐘、一次性；工作連線最長 12 小時，服務重啟失效。
- Token 只存在插件與服務記憶體，不寫進 Vault、data.json 或筆記。
- data.json 只保存服務網址與來源筆記路徑／雜湊。
- 可在 Mentor 撤銷連線，下一次 API 請求即拒絕。插件設定可清除本地憑證。
- 清除或撤銷憑證不會中止已經開始的 AI 執行；請另用「停止這次執行」。
- 配對權限：任務閱讀、建立、執行、交接與人工驗收；不允許角色設定、刪除資料、匯入 session 或任意產出目錄。
- 仍保留 Host／Origin／CSRF；插件透過獨立白名單橋接，不放寬網站同源限制。

## 主題、範本與移除

Theme 使用系統字型、Obsidian 變數與原創紙色／森林綠配色，無外部素材。範本只包含 Markdown、Properties、Callout 與連結，不要求 Dataview／Templater。

停用 Theme 回到其他外觀；停用插件不影響筆記原文。人工整理的範本與側欄保存的接手包仍可閱讀。正式 Mentor 任務檔仍在 MENTOR_HOME/vault，不因插件停用而搬移。

要升級，先備份示範庫與你保存的筆記，再手動替換插件的 main.js、organization.js、manifest.json、styles.css 或 Theme；不覆寫範本中已填寫的內容。正式庫升級流程仍待實機驗收。

## 使用量

每輪保存實際送出的 Prompt、回覆、字元與 UTF-8 bytes。成功的 Codex／Claude 呼叫會擷取 CLI 回報的用量，保存欄位來源與本機量測時間。缺少欄位、舊紀錄或失敗呼叫仍標未知，不以零或字元數代替。Claude 費用是 CLI 端估算，非實際帳單；不推算 Codex 費用。Codex 的 cached_input_tokens 是輸入中的快取部分；Claude 的 input_tokens、cache_read_input_tokens、cache_creation_input_tokens 是不同欄位，不混加後直接比較。

```sh
npm run measure:handoff -- /absolute/MENTOR_HOME/vault/TASK-id.md
```

比較同一份任務／歷史的完整交接與接手摘要大小。這不是 Token、成本或品質改善證明。人的修正與限制不為了達到 8,000 字元而刪除，過長會明確提示。實際模型 Token 基準仍待完成。

## 驗證範圍

已自動測試：原生插件關鍵方法的隔離測試、本機配對過期／單次使用／限流／撤銷、來源過期、建立任務冪等、計畫識別與版本、歷史快照、完整原文與摘要分離，以及既有回歸測試。

已用瀏覽器檢查：正式 UI 的工作卡、計畫預覽與退回修改。使用 fake CLI，故意讓原始 Obsidian 要求與寫死的簡報解讀不同，確認介面能讓偏差被看見；沒有把偏離目標的計畫批准或宣稱成果完成。

待驗證：Obsidian 桌面實機、Theme 的 Live Preview／閱讀模式、跨平台真實 CLI、真人理解測試、完整升級復原。這些不由 Node 測試或網頁截圖替代。

### CLI 用量格式來源

- [Codex 非互動模式](https://learn.chatgpt.com/docs/non-interactive-mode)：--json 的 turn.completed.usage；最終文字仍從 -o 讀取。
- [Claude 程式化執行](https://code.claude.com/docs/en/headless)：--output-format json 的 result／metadata；total_cost_usd 是 client-side estimate。

只保存白名單數值，不保存 CLI envelope 中的 session／帳號 metadata。此變更不會啟用 resume 或改變工具權限。比較兩個 Prompt 的真實用量仍需同模型、相同任務與品質驗證，不能用這次短句 smoke test 宣稱節省比例。

### 真實交接比較基準

`npm run benchmark:handoff` 只預覽虛構任務與大小；加上 --run、--provider、--model 與 --pairs 才呼叫真實 CLI。兩組為四次呼叫，會使用額度，不讀正式 Vault。[2026-10-22 實測](benchmarks/handoff-2026-10-22.md)保留四個樣本，資訊保留通過，但未證明穩定 Token 節省。
